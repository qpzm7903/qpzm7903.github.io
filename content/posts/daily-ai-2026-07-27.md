## ⭐ 今日最值得关注

### Kimi Code 的 Agent Core v2 正在把“能跑”改造成“可治理”

月之暗面的 [Kimi Code](https://github.com/MoonshotAI/kimi-code) 这两天没有发布正式版本，但主仓库出现了一组足够具体的架构进展，属于 7 月 23 日已报道项目的**实质更新**。首先，[状态容器提交](https://github.com/MoonshotAI/kimi-code/commit/7799bd7346aaee11ec2b6d6883e1e4fe5ab10717)为应用、会话和 Agent 三种作用域分别加入可观察的键值状态，并让调试器能按秒展示状态快照；这相当于把散落在各服务里的“记忆”搬进统一仪表盘。随后，[工具注册重构](https://github.com/MoonshotAI/kimi-code/commit/bf8e967d5c5c5dd458acd3319031993b8c53a44c)把内置工具改成按 Agent 作用域创建、按 Profile 策略激活的服务，未配置搜索提供方等能力时也不会在启动阶段把整个作用域拖垮。最新的[目标续跑修复](https://github.com/MoonshotAI/kimi-code/commit/0cef160c4b900a3d78212cd5da4b80d335ea0b6f)则让单轮达到步骤上限时继续追求既定目标，而不是在技术性上限处停住。三项改动合在一起看，重点不是多了一个显眼按钮，而是长任务 Agent 的状态、工具权限和续跑边界开始拥有更清晰的工程模型。对开发者来说，这类底层治理能力往往决定 Agent 能否从演示走向可调试、可恢复、可按角色收敛权限的生产系统；但目前仍是主分支开发进展，不应当写成已经发布的新版本。

> **原文金句**：“AgentLifecycleService.create runs one activation pass after restore and profile binding so tools reflect the Profile before the first turn.”
>
> 中文：`AgentLifecycleService.create` 会在恢复并绑定 Profile 后执行一次激活，使工具在第一轮之前就符合该 Profile 的策略。

## 📰 快讯

- **[Kimi Code：达到单轮步骤上限后继续目标执行](https://github.com/MoonshotAI/kimi-code/commit/0cef160c4b900a3d78212cd5da4b80d335ea0b6f)**：修复覆盖“正在执行目标”和“创建目标的这一轮就触顶”两种情况，避免长任务因为每轮步数保护机制而被误判为完成。它是运行控制修复，不是模型能力更新。
- **[Kimi Code：按 Profile 激活工具](https://github.com/MoonshotAI/kimi-code/commit/bf8e967d5c5c5dd458acd3319031993b8c53a44c)**：工具实例改为延迟解析，并随 `agent.status.updated` 重新检查 Profile 的工具策略。这样同一套 Agent 内核可以给不同角色装配不同工具面，而无需在模块加载时全部实例化。

## 📖 今日英语

- **profile-aware activation** — Kimi Code 提交原句：“AgentToolActivationService filters contributions by the bound Profile's tool policy.” 释义：感知配置角色的激活机制。为什么值得记：`profile-aware` 常用于描述会根据用户、租户或角色配置改变行为的系统。
- **per-scope keyed state container** — Kimi Code 提交标题：“add per-scope keyed state container.” 释义：按作用域划分的键值状态容器。为什么值得记：`scope` 在依赖注入和生命周期管理中常指对象存活及共享的边界。
- **resilient model catalogs** — pi v0.82.1 原句：“Faster, more resilient model catalogs.” 释义：更具韧性的模型目录。为什么值得记：`resilient` 常用来形容故障后仍能维持服务或恢复的系统。
- **reliability improvements** — Claude Code v2.1.220 原句：“Bug fixes and reliability improvements.” 释义：可靠性改进。为什么值得记：这是版本说明里概括稳定性工作的高频搭配，但信息较粗，阅读时仍应继续寻找具体变更。
