# 元数据与结构化数据规范（P3）

> 目标：让每篇文章的 `<head>` 与 JSON-LD 都"说真话"——语言对、摘要可用、图片有、体积不浪费。
> 本文是权威说明；`hugo.yaml`、`layouts/partials/templates/schema_json.html`、`scripts/gen-descriptions.py` 必须与本文一致。

## 1. 语言信号

| 位置 | 修复前 | 修复后 | 实现 |
|---|---|---|---|
| `<html lang>` | `en` | `zh-cn` | `hugo.yaml` 设 `locale: zh-cn` + `defaultContentLanguage: zh-cn` + `languages.zh-cn.label` |
| JSON-LD `inLanguage` | `en` | `zh-cn` | 同上次配置；模板取 `site.Language.Lang` |

根因：只设 `languageCode` 时 Hugo 的 `site.Language.Lang` 仍回退到 `en`（`hugo config` 可验证 `defaultcontentlanguage = 'en'`），
且 Hugo 0.158+ 已把 `languageCode` 标记为弃用、改用 `locale`。

## 2. 摘要（description）

- **优先级**：front matter `description` → 站点 `params.description` → 正文派生（兜底）
- **生成器**：`scripts/gen-descriptions.py`（按内容家族取候选，见脚本头注释）
  - `daily-*`：取「最值得关注」条目 → 拼成 `今日精选：A、B`
  - `*-update-*`：取首个功能小节首条 → 前面加标题（含版本号）
  - `weekly-review-*`：取导语（跳过"本期覆盖/周报只回读"这类元信息句）
  - 手写长文：取首个 ≥40 字的正文段落（跳过元信息行、表格行、有序步骤）
  - 三条滤镜：跨文章的模板句（≥5% 出现即视为 boilerplate）、markdown 残留、"暂无摘要/Generated by"
- **长度**：40~120 字（中位 96），超过在句读处截断并补 `…`
- **不覆盖手写**：脚本默认保留已有 `description`，需要重写必须显式 `--overwrite`
- **覆盖率**：9/366 → **366/366**

## 3. 结构化数据

覆盖主题 `layouts/partials/templates/schema_json.html`（比主题原版少 5 个问题）：

| 问题 | 主题行为 | 我们的做法 |
|---|---|---|
| 全文重复注入 | `"articleBody": <全文 plainify>` + `"description": <摘要>` | **删除 `articleBody`**（这是文章页 HTML 中位 38.5KB → 22.3KB 的主因） |
| author 嵌套错 | `"author": {"name": {"name": "OpenClaw"}}` | `"author": {"@type":"Person","name":"OpenClaw"}` |
| wordCount 失真 | `.WordCount` 对中文按空格断词（实测 477，严重偏低） | **不输出** `wordCount` |
| 缺 image | 无 `og:image` | 输出与 `og:image` 同源的 `image` |
| inLanguage 错 | `en` | `zh-cn` |

类型：首页 `Organization` + `sameAs`；文章页 `BreadcrumbList` + `BlogPosting`；列表页 `BreadcrumbList`。

**踩坑记录**：`<script>` 上下文里 `html/template` 会把字符串值按 JS 规则再转义，
`{{ $v | jsonify }}` 会产出 `"\"值\""`。必须写成 `{{ $v | jsonify | safeJS }}`。主题原文件用 `safeJS` 正是这个原因。

## 4. 社交分享图（og:image / twitter:image）

- 默认图：`static/images/og-default.jpg`（1200×630，63KB），由 `scripts/gen-og-image.swift` 用 CoreGraphics 生成（可复现、无第三方依赖）
- 接线：`hugo.yaml` 的 `params.images: ["images/og-default.jpg"]` → PaperMod 的 `get-page-images` 会作为兜底
- 单篇覆盖：front matter `images: ["..."]` 优先
- 效果：`og:image` + `twitter:image` + `twitter:card=summary_large_image` + JSON-LD `image` 四处同源

为什么用 JPEG 而不是 PNG：渐变背景 PNG 约 680KB，JPEG(q=0.85) 约 63KB，OG 抓取方对体积敏感。

## 5. 校验

```bash
bash scripts/verify-meta.sh --dir <hugo 构建目录>                 # 5 项结构校验
VNU_JAR=/path/vnu.jar bash scripts/verify-meta.sh --dir <dir>     # 追加 W3C vnu（0 error）
```

| 校验项 | 判据 |
|---|---|
| `<html lang>` | 抽样页全部 `zh-cn` |
| BlogPosting | 每篇恰好 1 个；`inLanguage=zh-cn`；无 `articleBody`/`wordCount`；author.name 为字符串；description ≤200；有 image |
| canonical | percent-decode 后与自身 URL 一致 |
| og:image | 标签存在，且对应文件在构建产物内 |
| description | ≥40 字、无模板残留 |
| 体积 | 文章页 HTML 中位 ≤ 40KB |
| vnu | 0 error（当前 4295 条 info/warning，全部来自主题的 SVG `aria-hidden`、vnu 的语言猜测、列表页无 h1） |

## 6. 已知遗留（不在 P3 处理）

1. **vnu 的 4128 条 `aria-hidden unnecessary`** 来自 PaperMod 的图标 SVG（`aria-hidden` + `hidden` 同时出现）。
   修它要 fork 主题模板，收益低；P6 里以"0 error"为门禁，warning 只记录。
2. **145 条"document appears to be written in English"**：工具更新类文章正文是英文 changelog，页面确实英文化；
   `lang=zh-cn` 是站点级声明，暂不为单篇切换（会引入 per-page lang 的复杂度）。
3. **18 条"没有 h1"**：列表/归档页由主题生成，无 h1。属可访问性问题，拟在 P4 的 hub 页模板里一并修。
4. **摘要质量**：自动生成的摘要可读但不是"人写的"。`docs/thin-content.csv` 与摘要中偏弱的部分（如周报、WSL2 指南）作为内容待办。
5. **主题升级**：`schema_json.html` 是覆盖文件，升级 PaperMod 后需与本文件 §3 比对差异。
